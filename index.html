The big idea behind TenderOS: heavy files never slow down the website, payments can never be charged twice, and the AI compares the tender directly against the user's company profile.

How a user goes from a raw 100 MB PDF to a finished Word bid package.

Three ideas that hold it together

  1. Heavy files never block the site

    The browser uploads straight to Cloudflare R2 with a 15-minute key, so the web server never carries the PDF.

  2. Payments can never be charged twice

    A Redis lock on the first click and a unique transaction ID in MongoDB make a double click harmless.

  3. The AI compares against the company

    Extracted tender rules are checked against the user's certifications, staff count and clearance to produce a 0–100 score.

What happens at each state

  1. STATE 1

    Upload link

    FastAPI checks the file is a PDF under 100 MB and hands the browser a 15-minute Cloudflare R2 link.

    R2FastAPI
  2. STATE 2

    PENDING_PAY

    The job waits for the $250 Paystation payment. A 5-minute Redis lock and a unique transaction ID stop double charges.

    PaystationRedis lock
  3. STATE 3

    QUEUED

    The paid job waits in the Redis line until a Celery worker is free; each worker takes one PDF at a time.

    RedisCelery
  4. STATE 4

    PROCESSING

    The worker streams the PDF, checks the first 3 pages for text, chunks it, calls the AI and scores the result.

    chunkersanitizerllm_router
  5. STATE 5

    UNREADABLE_SCAN

    An image-only PDF with no readable text is parked here instead of crashing.

    Admin: Route to OCR
  6. STATE 6

    REPROCESSING

    Optical software reads the text from the page images, then the job returns to processing.

    OCR
  7. STATE 7

    EVALUATED

    The user sees a 0–100% readiness score and an editable checklist, and can export a Word package.

    .docx report
  8. STATE 8

    FAILED (error)

    Something broke. An admin can send the job back to QUEUED with one click.

    Admin retry

Rules that hold at every state

  • A payment is locked in Redis for 5 minutes and must carry a unique transaction ID, so it is never charged twice.
  • All PDF text is wrapped in <tender_document_content> tags before the AI sees it, so hidden commands are treated as plain data.
  • Secret tenders go only to private OpenAI; normal tenders go to OpenRouter with prompt caching.
  • Every admin override is written to audit_logs.
  • The worker streams the PDF from R2 and never saves it to disk.

Numbered steps

  1. 1–2

    Select and pay

    The browser asks FastAPI for an upload link, sends the PDF straight to R2, and pays $250 on Paystation.

  2. 3

    Lock and queue

    FastAPI takes the Redis payment lock, records the receipt in MongoDB and queues the job.

  3. 4

    Stream and chunk

    The Celery worker streams the PDF from R2 and cuts it into 4,000-token chunks.

  4. 5

    Score and build

    The AI router sends Secret tenders to direct OpenAI and commercial tenders to OpenRouter. The worker scores and builds the .docx.

  5. 6

    Download

    The finished Word report is saved to R2 and the user gets a download link.

What changed in the v2.1 architecture?

LangChain is removed completely, and three small, focused files are added inside app/core/: chunker.py (exact 4,000-token slices), llm_router.py (Secret tenders to private OpenAI, normal tenders to OpenRouter with prompt caching) and sanitizer.py (wraps PDF text in safe XML tags).

Technical requirements

System layerTechnology usedWhy we use it
Web & API serverPython 3.11 + FastAPIServes both HTML pages and JSON API routes quickly from one place on Render.
Frontend UIJinja2 + Alpine.js + TailwindZero complex build steps. Pages load fast and buttons react smoothly in the browser.
Queue & locksRender Managed RedisHolds the waiting line for PDF jobs, live progress bars and 5-minute payment locks.
Background workerCelery 5.x (prefetch = 1)Reads heavy PDFs in the background one at a time so the website never freezes.
AI & token enginehttpx + tiktoken + Pydantic v2Replaces LangChain. Slices text cleanly and guarantees valid JSON answers every time.
Storage & databaseCloudflare R2 + MongoDB AtlasR2 holds 100 MB PDFs and Word files; MongoDB stores users, checklists and receipts.
